# テスト手順

- 狭い単体テスト: `npm run test -- src/integration/upstreamAdapter.test.ts`
- 型検査: `npm run typecheck`
- lint/format検査: `npm run lint`
- 本番ビルド: `npm run build`
- 全体: `npm run verify`
- 上流データ同期を含むリリース検証: `npm run release:prepare`
- スマホPoCのビルド・生成コード検証: `npm run test:mobile-poc`（[実機手順](testing/mobile-poc.md)）

ローカル導入後、対象ページで「接続済み」表示、対象外URLで非起動、破損した検証対象保存値で安全停止、コンソールに予期しない例外がないことを確認します。ランキングでは計算結果、キャンセル、古い結果の競合に加え、元ツールの個体変更をランキングタブへの移動時に読み直すこと、ランキングの個体操作で `PstIvState` と `PstPokeBox` が変更されないこと、共有計算条件 `PstStrenghParam` の変更が従来どおり反映されることを検証します。`RankingWorkspaceState.test.ts` は固定した元ツールの保存処理も使い、操作別の書き込みキーと保存schemaを検証します。

データパックのテストでは、同期済みJSONの受理、既知仕様だけを使う新ポケモンの追加、未知スキルを持つポケモンだけの除外、欠損データへのフォールバック、ネットワーク取得後の一括適用とキャッシュを確認します。

ページ起動時更新では、初期画面がネットワークを待たないこと、各ページ起動で取得すること、service workerの同時リクエスト共有と成功・失敗後の再取得、変更なしで通知・結果の失効が発生しないこと、計算中の更新待機、結果を保持した再計算案内を確認します。

Issue #54の実ブラウザ受入項目: 同じdistをChrome/Edgeへ読み込み、起動・再読み込み、複数タブ、オフラインからオンラインへの復帰、新ポケモン・イベントの反映、計算中のデータ更新と再計算表示を確認する。2026-10-02の実装環境ではCodex内蔵ブラウザのみ操作可能で、Chrome/Edgeの拡張管理画面とunpacked読み込みは利用できないため、この受入は手動確認が必要。

## リリース受入チェック

- ChromeとEdgeの最新安定版へ同じ `dist` を読み込む。
- ランキングタブが上段末尾に1つだけ表示される。
- 元ツールとランキングの選択色・インジケーターが重複しない。
- 6目的で必要な入力が表示され、代表条件を1回以上計算できる。
- 計算中の進捗、中止、完了、同順位、ページングを確認する。
- 条件変更後に古い結果と条件要約を残して再計算表示になる。
- 「編集」で元ツールへ移動し、変更後に再読み込みなしで条件を取得する。
- 元ツールのボックスから比較対象を選べ、ランキング側に編集操作がない。
- 元ツールで個体を変えてランキングへ移動すると個体編集画面に反映される。ランキング内の個体編集・ボックス選択・下段タブ切替では `PstIvState` と `PstPokeBox` が変わらず、元ツールへ戻っても元ツールの個体表示が変わらない。
- 詳細ダイアログのRP、エナジー、評価を切り替えられる。
- 未対応・互換性エラー時に推測結果を表示しない。
- 開発者ツールに未処理例外やCSP違反がない。
