# 上流データの自動反映（Issue #54・#87）

## 1. 目的

既存の計算方式で扱える新ポケモン・イベントを、ストア更新を待たずにランキングへ反映する。ポケモンの計算データと表示名の翻訳を同じ自動反映機能で扱い、新ポケモンも選択した言語で表示する。ページを開く・再読み込みするたびに確認する仕様について利用者と合意済み。

新スキル・新効果・アイコン、イベント名・スキル名・画面文言の自動更新、検証の許容範囲の一般的な拡大は対象外。受入で確認した料理イベントのスキル食材数1.5倍は、追加の合意により対応する。

## 2. 入力仕様

同梱データ、同梱commitが一致する検証済みキャッシュ、公式上流の `src/data/pokemon.json` と `src/data/event.json`、5言語の `src/i18n/{en,ja,ko,zh-CN,zh-TW}/pokemons.json` を使用する。差分取得ではなく全体取得とし、既存の計算データ検証を維持する。

翻訳JSONは `pokemons` の文字列辞書だけを受け付け、検証済みポケモン名に一致する項目に絞る。空文字、200文字を超える文字列、制御文字、HTMLやi18nextの補間・参照構文は除外する。旧キャッシュは翻訳なしで引き続き読み取れる。

### 同梱データと自動反映の関係

| 取込方法 | 計算データ | ポケモン名の翻訳 |
|---|---|---|
| 同じ上流版のデータと翻訳を含むビルド | 同梱データを使用 | 同梱訳を使用 |
| `sync:upstream-data` で最新JSONだけを同期 | ポケモン・イベント・フィールドJSONを更新 | 翻訳は同期しない。固定submodule由来の同梱訳とのずれがあり得る |
| ページ起動時の自動反映 | 検証済みの最新ポケモン・イベントJSONを適用 | 同梱訳に不足するポケモン名を公式の翻訳JSONから補い、保存する |

現在の同梱ポケモンについては5言語すべての同梱訳が揃っている。#87は、自動取込で追加されたタマゲタケ・モロバレルに同梱訳がない組合せで発生した。翻訳の取込は自動反映処理の一部であり、別の機能として有効化する必要はない。

## 3. 処理ロジック

初期データを読み込み画面を起動してから非同期で最新データを確認する。検証済み内容をキー順に正規化して比較する。変更時だけデータrevisionを更新し、結果を古いデータによる計算として扱う。進行中の計算がすべて終了するまで適用を待機し、計算に利用する上流配列を途中で差し替えない。

取得・ブラウザ保存はChromium runtime、検証と適用はintegration、翻訳登録はランキングUI境界が担当する。同梱訳を優先し、取得訳は不足する名称だけ補う。英語名fallbackは英語辞書に登録し、他言語に英語を埋めて後日の翻訳を妨げない。翻訳だけの変更も既存revisionで通知する。

表示言語は元ツールの保存設定を優先する。設定未保存時はブラウザ言語を初期値とし、元ツールの設定へ書き込まない。

## 4. 出力仕様

取得したデータを検証後にキャッシュへ保存する。変更があれば以降の計算へ反映する。計算済み結果は保持し、自動再計算しない。上流所有の保存値は書き換えない。

ポケモン名の訳も計算データとともに保存し、再読み込み時に利用する。選択候補・結果・詳細の既存翻訳関数に同じ名称辞書を提供する。

## 5. 画面仕様・モック

ランキング画面上部に既存MUI Alertと同じ幅で状態を表示する。

翻訳の取込に専用の画面・設定は追加しない。日本語設定では `Foongus → タマゲタケ`、`Amoonguss → モロバレル`、英語設定では原名を表示する。上段の「ランキング」タブは現在、日本語固定とする。

| 状態 | メッセージ |
|---|---|
| 確認中 | 最新データを確認中です。 |
| 変更なし | 確認表示を解除し、通知なし |
| 更新済み | 最新データを反映しました。 |
| 計算中に取得 | 新しいデータを取得しました。計算終了後に反映します。 |
| 失敗 | 最新データを確認できませんでした。保存済みデータまたは同梱データを使用しています。 |
| 更新前の結果 | データが更新されました。再計算してください。 |

未対応項目の警告と条件変更の再計算表示を維持する。

データ更新前の結果では数値と条件一覧を保持する。上流の詳細画面は最新のイベント定義を使って再計算するため、データが古い結果からの個体詳細表示は再計算まで停止する。比較個体の編集値は維持し、次の計算では最新ポケモンデータへ結び直す。

## 6. 元ツールとのインターフェース仕様

既存integrationの検証・適用境界を利用する。UIには型付き状態・購読・revisionを公開する。データ更新時は共有計算条件と未対応イベントを読み直し、新ポケモンの選択候補を更新する。

実行時に固定submoduleは変更しない。取得したJSONは評価せず、検証済みの名称辞書だけを型付きstatusから読み取る。既存の未知仕様除外を維持する。

## 7. Chrome拡張固有仕様

service workerで固定の計算JSON 2 URLとポケモン名の翻訳JSON 5 URLとアイコン定義の固定1 URLを取得し、進行中のリクエストを複数タブで共有する。終了後は成功・失敗とも共有Promiseを破棄し、次のページ起動で再確認する。対象ページ・拡張IDを検証し、任意URL要求は受け付けない。追加権限・定期タイマー・ブラウザ起動フックは使わない。旧session確認済みキーは使用せず、自動削除もしない。

## 8. 例外・エラー時の動作

通信・検証・キャッシュ保存失敗時は既存データを維持する。再読み込みで再試行する。未知仕様は既存の局所除外ルールを適用する。ユーザーデータを送信しない。

翻訳の通信失敗・不正値は言語単位で既存の検証済み訳を保持する。計算JSONが正しければ計算データ更新を妨げない。利用可能な訳がなければ英語名fallbackを使用し、次のページ起動で再試行する。取得訳で同梱訳を上書きしない。

## 9. 未決事項・検証

受入時に料理イベント第3回のskillIngredient: 1.5が除外されることを確認したため、利用者の指示により1.5を許容値へ追加する。上流の計算コードとsubmoduleは変更せず、既存のingredientMagnet: 1.5との計算結果一致と端数切り捨てを契約テストで確認する。他の未対応倍率・未確定ポケモンは引き続き除外する。

実装対象の未決事項なし。単体・契約テスト、npm run verify、Chrome/Edgeのunpacked受入で確認する。公開は別途レビューとリリース手順に従う。両JSONのcommit固定取得は今回の範囲外。

名称はネットワーク適用・キャッシュ再起動・失敗後の再試行・英語fallback後の日本語反映・同梱訳の維持・不正翻訳除外・旧キャッシュ互換性を検証する。#87の修正候補は248テストとCI成功、利用者によりChrome/Edge両方の画面確認済み。追加変更後の0.3.1候補は別途受入が必要であり、ストア未公開。

## 画像の自動反映（#89）

1. 目的: 新ポケモンの灰色プレースホルダーを、公式元ツールと同じアイコンへ更新する。画像も既存の自動反映の一部とする。
2. 入力: 公式 `src/ui/IvCalc/PokemonIconData.ts` の図形オブジェクト。500 KB以下の対応する定義形式だけをJSONへ変換して読む。取得ソースを実行しない。
3. 処理: 検証済みポケモンID・対応フォームのみ受理。矩形の有限値・範囲、配列の件数、色番号と6桁の色コードを検証する。integrationに置く。
4. 出力: 通常色・色違いの図形と配色を型付きpackに含め、既存の公式UIが読むメモリー上のアイコン表へ適用する。保存値は拡張専用キャッシュのみ。
5. 画面: 既存の候補・比較個体・結果・詳細のアイコン位置とサイズを維持する。専用設定は追加しない。取得後はmemo化された公式アイコンも再描画する。
6. 上流境界: 同梱表をfallbackとして保持し、受理したデータだけを適用。上流ファイルや保存設定を変更しない。固定commitは互換性PRでのみ更新する。
7. Chromium: 既存の固定GitHub取得先権限とservice workerを利用し、リクエスト共有・タイムアウト・次回起動での再試行を維持する。追加権限なし。
8. エラー: 画像取得失敗・形式変更・不正データ時は既存キャッシュと同梱画像を維持する。計算JSONと翻訳の取得を妨げない。画像が一度も取得できない新IDは既存の灰色表示とする。
9. 検証: 固定上流形式、フォーム、通常色・色違い、不正値・実行式の拒否、画像のみ更新、キャッシュ復元、取得失敗時の保持をテストする。更新後Chrome/Edge受入は未実施。
