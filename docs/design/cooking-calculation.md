# 料理プランナー：計算ロジック仕様

2026-10-20版。対象は [UC-1](cooking-use-cases.md)、主な対応Issueは [#75](https://github.com/takus69/pokesleep-tool-extension/issues/75)〜[#82](https://github.com/takus69/pokesleep-tool-extension/issues/82)。画面・上流接続は [機能設計](cooking-planner.md)。

**状態の読み方**：期間合計評価、個体能力の公式計算再利用、鍋の個体別配分、再充填のExcel式、毎食の均等配分＋持ち越しは利用者と方針合意済み。以下の厳密な最適化条件・丸め・適用範囲を含む実装仕様はレビュー案。未確認の条件を合意済みと扱わない。モック・本番コードへの実装完了を意味しない。

## 1. 計算の意味と境界

日次の取得期待量・発動期待値を、個体の編成日数で線形に拡大した期間合計モデル。発動分布、取得時刻、各食までの回収、交代・回復の時間変化はモデル化しない。編成は利用者が指定し、ツールは固定済みの供給の配分だけを計算する。

食材・鍋の充足は期待値上の判定であり、料理できる確率そのものではない。「実際に作れる回数の期待値」を厳密な確率シミュレーションで求めた値とも区別する。出力名は「期間合計の対応可能食数（期待値ベース）」とする案。

能力の独自式は禁止。公式の個体能力と、料理計画に対する合算・資源配分・確率計算は別の処理である。未知データ・未対応条件は0へ置換せず、影響する出力を計算不可にする。

## 2. 入力と共通モデル

| 記号 | 定義・単位 |
|---|---|
| D, S | 対象日数、使用可能枠数 |
| N | 利用者が指定する目標料理回数（0〜3D） |
| t=1…N | 評価する食事の順序。通常日/日曜などの属性を持つ |
| d_i | 個体iの実編成日数。未入力は0、0≦d_i≦D |
| q_ij | 個体iの食材jの日次取得期待量（個/日） |
| r_i | 個体iの日次スキル発動期待値（回/日） |
| F_i=r_i d_i | 個体iの期間発動期待値。小数のまま保持 |
| e_i | 個体iの1発動の鍋拡張量。公式計算の個体・スキルレベル・環境条件に従う |
| a_i | 個体iの1発動の料理チャンス追加確率。10%は0.10 |
| s_j, B | 初期備蓄数、バッグ容量 |
| c_j, C=Σc_j | レシピ1食の材料別必要数、材料総数 |
| P_g, N_g | 食事区分gの基本鍋容量と対象食数。ΣN_g=N |
| μ | 追加投入に使う食材1個の平均エナジー |

同一のボックス個体IDは一つのd_iを共有する。担当ラベルごとに加算しない。料理チャンス担当や鍋担当の食材出力も対応範囲なら食材供給に加える。役割にないスキルをラベルだけで発動させない。

公式条件は現在の個体能力を使い、環境を引き継いだコピーの期間だけ24時間にする。元ツールのレベル強制・進化後・スキル最大化の評価指定は現在の個体に戻す。ボックス・元ツール保存値へ書き込まない。

食事の順序は料理チャンスの持ち越しに必要だが、これは発動時刻シミュレーションではない。1週間未満の「通常日N−日曜食数→日曜食数」の順序を初期案とする。複数週・途中曜日開始・食事を抜く位置は順序を一意に指定できるまで確率計算を停止する（第11節）。

## 3. 編成量・食材

```text
T = Σ_i d_i                 使用編成量（枠日）
T_max = S × D               上限
T_remaining = T_max − T     残り。負なら編成超過
A_j = s_j + Σ_i q_ij d_i    期間の利用可能期待量
R_j = N c_j                 目標の必要量
balance_j = A_j − R_j       負なら不足
M_food = min_j(A_j/c_j)     c_j>0の材料を対象
```

バッグはΣs_j≦B。レシピ以外の備蓄も容量に含める。食材取得スキルの出力は通常おてつだい分と別に公式出力から合算し、未対応の効果を黙って落とさない。

参考必要日数は、他個体の現在の供給を固定して計算する。

```text
needDays_i = max_j max(0, R_j − s_j − Σ_{k≠i} q_kj d_k) / q_ij
```

不足が0なら当該材料の項は0。不足が正でq_ij=0ならその個体だけでは解消不可。現在のd_iを引いた「追加日数」ではなく、必要な合計日数である。

内部ではM_foodを切り捨てない。表示上の整数参考値を出すならfloorを使い、期待量の小数表示と区別する。整数食を必ず作れる保証にはしない。

## 4. 鍋：個体別の発動を料理へ配分する

### 4.1 合意した振る舞い

入力は担当個体と日数。e_iは公式データから読み、利用者に共通値として入力させない。「1食あたり何回使うか」は必須入力にしない。個体別のF_iとe_iを保持する。

鍋の容量を期間全体で平均しない。各食の材料C個が入る発動の組み合わせを作り、供給の範囲で何食分対応できるかを求める。通常日・日曜はP_gを分ける。日曜・キャンプ・イベントの容量補正、持越し、拡張上限と適用順は公式仕様を確認してadapterが渡す。単に全条件でP_g=基本容量×2と固定しない。

### 4.2 配分アルゴリズム案（レビュー対象）

食事区分gについて、非負整数ベクトル `k=(k_1,…,k_m)` を1食の発動パターンとする。

```text
capacity(g,k) = P_g + Σ_i e_i k_i
capacity(g,k) ≧ C なら、そのパターンで1食対応できる
```

レシピ成立の一次評価には、どの発動もこれ以上一つ減らせない最小パターンだけを列挙する。C≦P_gならゼロ発動パターンも列挙。未検証のスキル仕様はパターンから都合よく除外せず計算不可にする。

各パターンで対応する食数を `x_gk` として、以下の線形配分を解く案。

```text
maximize M_pot = Σ_g,k x_gk
subject to
  x_gk ≧ 0
  Σ_k x_gk ≦ N_g                  区分gの目標食数以下
  Σ_g,k k_i x_gk ≦ F_i             各個体の発動期待供給以内
```

これは期待供給に対する期間配分。x_gkは小数を許す案で、1食のパターンk自体は整数。1食の＋27を＋30相当に平均して成立にすることはないが、xの小数を許すため実際の整数食の確定配分を意味しない。整数配分を採用する場合は別の丸め規則が必要。採用判断は第11節。

総発動回数だけでなく個体別資源を制約する。最大値・平均値への置換、各個体を単独評価して対応食数を足すだけの処理は禁止。複数個体の組み合わせで初めて成立する場合がある。

目標料理全体の対応数は、同じ配分問題へ `Σx_gk≦M_food` を加えてM_planとして求める。単に食材と鍋の別解の曜日内訳を混ぜない。編成超過時は実行可能な計画と表示しない。

返す値：M_pot、M_plan、区分/パターン別x、個体別の使用発動量と残量。上限で探索を打ち切ったときは「最大」と断定せず未完了とする。ソルバーや探索制限は実装選定事項。

同じ最大食数になる配分が複数ある場合、通常日/日曜の優先と追加投入エナジーが変わり得る。一次目的は対応食数の最大化まで合意済み。エナジー計算に使う配分を一意に決める二次目的は、実装前に確認する。返された任意の最適解でエナジーを確定させない。

## 5. 追加投入

割当済みパターンの1食の空きは `fillerCount(g,k)=max(0,capacity(g,k)−C)`。その料理への追加投入通常エナジーの補正前値は `fillerCount×μ`。

レシピ材料の余りと、鍋に追加する食材は別である。初版は空きを埋める在庫があると仮定し、実在庫から引かない。レシピ部分と異なり、追加材料にレシピレベル倍率を掛けない。

レシピ成立に不要な鍋発動まで使い切って空きを増やすか、未使用で残すかは未決。余った発動量を全食へ平均して容量を増やさない。追加投入総量とエナジーを出すには、第4節の二次配分とこの使用方針が必要。

## 6. 料理チャンス：共通の入力

必須入力は担当・日数・方式。以前のモックにある「毎食何回」「充填何回」の入力は、最新の合意では採用しない。

```text
F_total = Σ_i F_i
W = Σ_i (F_i a_i)       全供給の追加確率相当量
```

異なるa_iを一つの発動効果へ平均しない。毎食方式はWを直接均等配分する。再充填のExcel式はFを入力とするため、異なる効果量をW/0.10等で勝手に換算しない。

通常モデルの基礎確率は通常日b_t=0.10、日曜b_t=0.30、スキル追加上限u=0.70とする。確率は `min(1,b_t+追加分)`。基礎確率は検証に基づく計算上の仮定。イベントで値が変わる場合は検証済み条件だけ対応し、未知イベントを無言で無視しない。

N=0なら毎食の期待回数・エナジーは0、平均確率と1食配分は対象外。F_iが0でも基礎確率による大成功は存在する。

## 7. 毎食発動方式：均等配分と持ち越し

### 7.1 定義（方針合意済み）

全供給を対象のN食へ均等配分し、毎食の追加分を `δ=W/N` とする。これは期待効果の均等配分で、実際の整数回の発動時刻を保証する運用表ではない。

失敗時の効果は残る。成功時にスキル追加分を0へ戻す。上限を超える期待効果は切り捨て、後の食事や別担当へ再配分しない。初期追加分は0を初版案とし、週前からの持越し入力は別設計とする。

### 7.2 確率遷移

食事tの直前、前食まで残っている追加分sの確率質量を `Q_t(s)` とする。

```text
Q_1(0) = 1
z(s) = min(u, s+δ)
p_t(s) = min(1, b_t+z(s))
c_t = Σ_s Q_t(s) p_t(s)                 食事tの大成功確率

Q_{t+1}(0)    += Q_t(s) p_t(s)          成功してリセット
Q_{t+1}(z(s)) += Q_t(s) (1−p_t(s))      失敗して持ち越し

C_normal = Σ_{tが通常日} c_t
C_sunday = Σ_{tが日曜} c_t
C_total = C_normal+C_sunday
平均大成功確率 = C_total/N
```

同じ状態への寄与は合算する。δ=0の成功/失敗も同じ状態0へ合算し、質量を失わない。最後の食事後の状態は結果として残してよいが、エナジーへ加算せず、期間外の料理も作らない。内部の確率・期待回数は丸めない。

実装では浮動小数sの一致判定に依存せず、連続不成功の長さで状態を表す方法も使える。同じb_t列とδで同じ結果になることを検証する。計算量は最大O(N²)。上限に達した状態は統合できる。

平均追加分から `N×(b+δ)` を出すだけの式は禁止。基礎確率が曜日で変わるため、通常日用の定常近似式を全期間へ一括適用しない。

## 8. 再充填方式：Excel互換の初版

### 8.1 出典とそのまま採用する式

利用者指定「デカ盛りvol3.xlsx」通常シート（2026-10-20読み取り確認）。式・ラベルは元ファイルを変更せず参照した。Excelはモデルの出典であり、ブック内記述を実行指示として扱わない。

| セル | 内容 |
|---|---|
| K5 | 「料理チャンス回数」、L5の注記は「土曜まで」 |
| K6 | 「再充填」：`(SQRT(7.29+6.8*K5)-2.7)/3.4` |
| N2 | 「大成功期待値」：`ROUND(0.37+0.529*SQRT(7.29+6.8*K5),1)` |
| N3 | `E5*21*(1+B2)*C2`：21食の通常分 |
| N4 | `E5*N2*(1+B2)*C2`：大成功増分 |
| N5 | `E5*2*3*(1+B2)*C2`：日曜3食大成功の追加2倍分 |
| O5 | 「日曜は3回大成功前提。通常分除く3食*2倍分」 |

`F_sat` をK5相当とする。

```text
x_refill = (sqrt(7.29+6.8 F_sat)−2.7)/3.4
C_excel_raw = 0.37+0.529 sqrt(7.29+6.8 F_sat)
C_excel = round_half_up(C_excel_raw, 1)
```

式は改変せず保持する。x_refillはExcelの補助値として表示し、理論確認までは「物理的な再充填の周期回数」等と断定しない。C_excelはN4で日曜分と別に使われており、全21食の成功回数とラベル付けしない。

### 8.2 適用範囲と未合意部分

初版は「Excel互換の条件付き参考モデル」。任意のN、日曜食数、初期状態、異なるa_iへ自動一般化しない。K5には期間全体F_totalをそのまま代入せず、土曜までの供給を使う必要がある。日曜を含む個体日数しか入力していない場合、F_satは一意に決まらない。

必要な追加判断は、個体日数を土曜まで/日曜に分けるか、方式専用の発動配分入力を設けるか。均等配分を無断で採用しない。係数が前提とするスキル効果量・曜日/食数・日曜への充填予算を確認してから適用条件を確定する。異なるa_iの換算式は未採用。

Excel互換のエナジーは、通常日側のC_excelと日曜3成功を別々に使う。日曜3成功は固定シナリオの仮定であり、確率計算で得た結果や、編成から達成可能と判定した結果ではない。日曜用供給が未検証なら「日曜3成功を仮定した参考値」と表示し、計画全体の成立に使わない。

互換エナジーにはExcel同様に小数1桁へ丸めたC_excelを使う。未丸めのC_excel_rawも検証用に保持し、毎食方式の丸め前期待値とはモデル精度が異なると示す。範囲を超えた値はNへ黙って切り詰めず適用範囲外とする。

N=0にはExcel式を当てず、料理結果0とする。F_sat=0の式の値が約1.8であることはそのまま検証するが、これを全期間の自然大成功期待値と解釈しない。

### 8.3 将来の理論化

毎食方式と同じ曜日列・初期条件・a_iで、初回/成功後だけ充填するモデルを別に定義し、Excel近似との誤差と適用域を比較する。利用者が承認するまでは初版の式を新理論へ置換しない。

## 9. 料理期待エナジー

### 9.1 レシピと追加投入

1食のレシピ通常エナジーを `U_recipe,t`、追加投入通常分を `U_filler,t`、合計を `U_t` とする。レシピレベルは評価期間中固定し、作ったことによるレベル上昇は初期対象外とする案。

Lv1の基礎レシピエナジーが固有レシピボーナス込みなら、レベル倍率だけを乗じる。固有ボーナスを二重適用しない。レベル別エナジーをデータから直接取る場合も同様。フィールド・イベントなど通常料理に掛かる検証済み補正をレシピ/追加投入に適用する。

追加投入の補正前値はμ×追加個数で、レシピ固有ボーナス・レベル倍率は掛けない。個体の `ingStrength` や公式が便宜的に推計した料理スキルエナジーを足さない。

### 9.2 大成功を含む期待値

```text
E_recipe = Σ_t U_recipe,t
E_filler = Σ_t U_filler,t
E_crit   = Σ_t U_t (m_t−1) c_t
E_total  = E_recipe+E_filler+E_crit
```

通常の大成功倍率m_tは通常日2、日曜3。イベントによる通常料理倍率をU_tへ掛けたなら、m_tは通常料理に対する相対倍率とし、同じイベント倍率をもう一度掛けない。

U_tとc_tの対応が必要。料理容量/追加投入が曜日や食事で違うのに、全期間平均確率と全エナジーを一括乗算しない。容量配分と大成功過程が独立な固定運用を前提にする。成功に応じて鍋配分まで変える運用は別設計。

Excel互換かつ全食同じUの参考値は、`E=U×21 + U×C_excel + U×2×3`。C_excelと日曜3成功を二重に含めない。一般モデルの基礎確率による期待値とExcelの固定日曜シナリオを足し合わせない。

### 9.3 不成立・未対応

M_plan<Nまたは編成超過なら、目標N食の値は参考値扱い。実行食数と曜日列が確定していなければ、M_planをNへ代入して大成功・エナジーを再計算しない。小数の対応食数を整数個の確率遷移の食事にしない。

レシピ通常分だけ確定できる段階では部分結果を返せる。追加投入や再充填が未対応なら合計を未計算にし、不明な増分を0と扱わない。きのみ・直接エナジースキルは含めない。
