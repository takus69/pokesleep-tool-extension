# 元ツール連携仕様

対象originは `https://nitoyon.github.io`、対象pathは `/pokesleep-tool/` 配下です。初期プローブは `#root` の存在と、存在する場合のみ `PstIvState` がJSON objectかを確認します。保存値は変更しません。

候補比較:

| 方法 | 変更耐性 | リスク | 方針 |
|---|---:|---|---|
| 表示DOMの解析 | 低 | 文言・MUI構造変更で破損 | 最小の存在確認だけ |
| localStorageの検証付きdecode | 中 | 非公開スキーマ変更 | 利用者入力の取得候補 |
| page worldへの注入 | 低 | 内部React/CSP/MV3へ密結合 | 原則不採用 |
| 必要な静的データ・計算を同梱 | 高 | データ更新が必要 | ランキングの中心 |
| 上流の非実行JSONを検証して取得 | 中 | ネットワーク・スキーマ変更 | 新ポケモン・イベントの早期反映 |

adapterの返却値は共通型または型付きエラーです。不明な値、欠落、破損、未対応版ではfail closedし、計算を開始しません。将来decoderにはスキーマ版、範囲検査、fixture、移行処理を追加します。

上段タブは個数や表示文言で特定しません。sticky計算領域の直下にある最初のMUIタブ列を上段として検出し、既存タブの末尾へ拡張タブを追加します。これにより「チーム」等の上流タブ追加を許容しつつ、下段のポケモン／ボックスを誤認しないようにします。上段の階層契約を確認できない場合は挿入せず停止します。

計算条件の変更判定は `PstStrenghParam` の生JSONをキー順に正規化して行い、ランキング側の条件で置き換える `level`、`evolved`、`maxSkillLevel` だけを除外します。値のdecodeと変更検知を分けるため、拡張がまだ知らないイベント名も変更として検出します。

実行時データ更新元は `raw.githubusercontent.com/nitoyon/pokesleep-tool/main/src/data` の `pokemon.json` と `event.json` です。JSONをコードとして評価せず、既知スキーマと許容値を検証します。新ポケモンが既知のタイプ、食材、メインスキル、形態だけで構成される場合はランキングへ追加します。未知の計算仕様を含むポケモンまたはイベントだけを除外し、警告を表示します。新フィールドの計算規則と新しい計算式は拡張本体の更新対象です。
